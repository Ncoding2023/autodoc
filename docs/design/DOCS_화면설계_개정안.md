# DOCS 화면설계 개정안

작성일: 2026-10-23 · 상태: 사용자 검토용 초안

## 목적과 적용 범위

인수인계서·업무 매뉴얼·가이드처럼 반복 작성하는 문서를 기존 DOCX 양식으로 완성한다.
웹에서는 양식에 연결된 항목의 내용만 입력한다. 글꼴·로고·표 배치를 자유롭게 편집하는 Word 편집기는 만들지 않는다.

화면 원본은 `AutoDoc_화면설계서.drawio`의 09~14 페이지다.
`AutoDoc_DOCS_화면설계_검토.html`은 해당 개정안의 읽기용 화면이며, 상단 화면 선택만 동작한다.
기존 01~08 페이지는 보존했다. 02·03·05·08의 DOCS 부분은 이전안이며 본 초안 검토 후 교체할 대상이다.
SHEETS 작업은 보류한다. 기존 설계의 공유·버전·Drive 기능도 이번 구현 범위에 추가하지 않는다.

## 초안의 전제

- 초기 지원 파일은 DOCX다. PDF/HWP의 빈칸을 자동 분석하는 기능은 포함하지 않는다.
- 양식 등록자는 변경할 위치에 `{{담당자}}`, `{{업무절차}}` 같은 입력 표시를 준비한다.
- 시스템은 입력 표시를 읽어 항목을 만들고, 등록자는 표시 이름·형식을 확인한다.
- 문서 작성자는 입력 표시를 편집하지 않고 등록된 양식을 선택해 내용만 작성한다.
- 회사 양식 업로드가 부담스러운 사용자는 준비된 기본 템플릿으로 시작한다.
- 입력 항목 설정은 DOCX 안에 있는 표시와의 연결 설정이다. 화면에서 항목을 추가한다고 원본의 입력 위치가 자동으로 생기지 않는다.

위 방식은 구현 범위를 정하기 위한 제안이다. 임의 문서 업로드만으로 모든 입력 위치를 알아내는 방식으로 확정된 것이 아니다.

1단계에서 구체화한 양식 표시·키·저장 규칙은 `DOCS_양식규칙과_데이터구조.md`를 기준으로 한다.
항목명 변경을 위해 DOCX에는 `{{담당자.label}}` 이름 자리와 `{{담당자}}` 내용 자리를 함께 둔다.

## 09 · 전체 흐름

양식 등록: 템플릿 관리 → DOCX 업로드 → 입력 항목 확인 → 템플릿 저장.

문서 작성: 새 문서 → DOCS → 기본 / 내 템플릿 선택 → 항목별 입력 → 임시저장 또는 문서 생성 → DOCX 다운로드.

기존 문서 수정: 문서 목록 → 상세 → 이어서 수정 → 저장 / 다시 생성.
입력값은 개별 문서에 저장하며 템플릿 원본을 변경하지 않는다.

## 10 · 양식 업로드

- 진입: 템플릿 관리의 DOCS 양식 등록 또는 템플릿 선택의 양식 등록 버튼.
- 파일 끌어놓기와 파일 선택을 제공한다.
- 파일 선택 전에 입력 표시 준비 방법과 샘플 DOCX 다운로드를 안내한다.
- 선택한 파일 이름과 입력 표시 탐색 결과를 표시한다.
- 입력 표시가 없으면 샘플·준비 방법·다시 업로드를 안내하고 진행을 차단한다. 일반 문서의 내용 전체를 입력창으로 자동 전환하지 않는다.
- DOCX 아님, 손상 파일, 암호화 등 읽을 수 없는 파일, 지원하지 않는 구성은 구체적 사유와 재시도를 제공한다.
- 업로드 처리 중 중복 요청을 막는다. 실패 후 다시 선택할 수 있고 취소하면 템플릿을 저장하지 않는다.

## 11 · 입력 항목 설정

- 왼쪽: 원본 양식 미리보기. 여러 페이지는 페이지 이동·스크롤로 확인한다.
- 오른쪽: 템플릿 이름, 추출된 표시, 작성자가 볼 항목 이름, 입력 형식. 필수 여부 열과 체크박스는 제공하지 않는다.
- 초기 입력 형식은 짧은 글 / 긴 글 / 날짜로 제안한다.
- 같은 표시가 여러 위치에 있으면 항목은 하나로 묶고, 문서 생성 시 같은 값을 모두 반영한다.
- 원본에 존재하는 표시와 설정 항목을 일치시킨다. 항목 이름 미입력, 연결 누락 등은 해당 위치에 오류를 표시한다.
- 원본 수정이 필요하면 이전 단계에서 파일을 다시 업로드한다. 기존 항목 설정이 초기화될 경우 미리 안내한다.
- 양식 미리보기 실패 시 다시 시도와 원본 다운로드를 제공한다. 확인용 체크박스와 확인 여부에 따른 저장 차단은 두지 않는다. 항목 검증을 통과하면 저장할 수 있다.
- 저장 실패 시 현재 설정을 유지한다. 저장 성공 후 템플릿 목록으로 돌아가고 등록한 양식을 선택할 수 있다.

## 12 · 템플릿 선택

- 기본 템플릿과 내 템플릿을 구분하고, 선택한 양식의 미리보기와 입력 항목을 보여준다.
- 완료 상태의 템플릿만 문서 작성에 사용한다.
- 목록 로딩, 템플릿 없음, 조회 실패 상태를 구분한다. 빈 기본 목록에는 재시도, 빈 내 목록에는 양식 등록을 제공한다.
- 템플릿 선택 전에는 작성 시작을 비활성화한다.
- 기본 템플릿은 업로드 없이 바로 작성한다. 사용자는 기본 템플릿 원본을 직접 수정하지 않는다.
- 템플릿 삭제·접근 불가 시 목록으로 돌아가 다시 선택하도록 안내한다.

## 13 · 항목별 작성

- 문서 제목은 목록에서 구분하는 이름이며, 양식에 들어가는 제목과 반드시 같은 항목은 아니다. 문서 내부 제목도 바꿔야 한다면 양식에 별도 표시를 둔다.
- PC는 왼쪽 양식 미리보기, 오른쪽 입력창으로 구성한다. 긴 항목은 여러 줄 입력을 제공한다.
- 모바일은 입력 / 미리보기 전환으로 구성하며 전환할 때 입력값을 유지한다.
- 미리보기는 갱신 버튼으로 현재 입력을 반영한다. 표시 중인 미리보기 이후 입력이 달라지면 갱신 필요 상태를 보여준다.
- 미리보기와 임시저장은 별개 동작이다. 자동저장은 초기 범위에 포함하지 않는다.
- 임시저장: 항목 내용 미입력을 허용하되 문서 제목과 입력된 값의 형식은 확인한다.
- 문서 생성: 문서 제목·항목명·입력된 값의 형식을 검증하고, 문서 데이터를 저장한 뒤 저장된 내용으로 DOCX를 생성한다. 항목별 필수 설정은 사용하지 않는다.
- 실패 시 입력을 유지하고 원인과 재시도를 제공한다. 항목 오류는 해당 입력창 옆에 표시하고 첫 오류로 이동한다.
- 변경 후 이탈 시 저장하지 않은 내용이 있음을 알린다. 저장하지 않고 나가기 / 계속 작성 선택을 제공한다.
- 수정 중 템플릿을 다른 양식으로 변경하는 동작은 초기 범위에서 제외한다.
- 항목명과 내용 입력칸을 같은 화면에 배치한다. 항목명에 직접 입력해 수정하며 별도 화면이나 팝업을 열지 않는다. 입력 내용과 위치는 유지한다.

## 14 · 생성 결과와 다운로드

- 생성 중 / 생성 완료 / 생성 실패를 색상과 상태 텍스트로 구분한다. 처리 중 중복 생성은 막는다.
- 생성 완료: 결과 미리보기, DOCX 다운로드, 이어서 수정, 문서 목록을 제공한다.
- 생성 실패: 저장된 입력값은 유지한다. 다시 생성하거나 이어서 수정할 수 있다.
- 다운로드 실패: 생성 결과를 유지하고 다운로드만 재시도한다.
- 결과 미리보기 변환만 실패하면 DOCX 다운로드는 제공한다. 미리보기 실패를 생성 실패로 표시하지 않는다.
- 파일 생성 후 내용을 수정하면 기존 파일을 최신 파일로 표시하지 않는다. 현재 내용으로 다시 생성한 후 최신 파일 다운로드를 제공한다.
- 로고·표 등 원본 서식을 활용하지만 내용 길이에 따라 표 높이, 줄바꿈, 페이지 수는 달라질 수 있다.

## 항목명 직접 편집 · 11·13 화면 공통

- 11페이지는 등록할 양식의 항목명을 바로 입력해 설정한다. 13페이지도 내용 입력창 위의 항목명을 바로 편집한다. 템플릿 목록 이름 변경이 아니며 별도 15페이지는 두지 않는다.
- 예: `담당자 / 김담당` → `업무자 / 김담당`. 입력값 `김담당`, 입력 형식과 양식 내 위치는 유지한다.
- 항목명 입력칸을 직접 편집한다. 별도의 수정 버튼·적용 팝업·확인 체크박스는 두지 않는다. 공백 이름은 허용하지 않으며 길이 제한은 구현 전 정한다.
- 11페이지의 변경은 템플릿 저장 시 반영한다. 13페이지의 변경은 현재 문서에만 적용되는 임시 변경이다. 문서 저장 시 항목명과 입력값을 함께 보관하며 재진입해도 변경한 이름을 표시한다.
- 미리보기를 갱신하거나 DOCX를 생성할 때 같은 항목명을 사용한다. 기존 원본의 고정 문자열을 무작정 찾아 바꾸지 않는다.
- 이를 위해 양식은 입력값 위치뿐 아니라 변경 가능한 항목명 위치도 식별할 수 있어야 한다. 원본의 고정 텍스트만으로는 임의 항목명 변경을 보장할 수 없다. 이름 자리 `.label`과 내용 자리를 같은 키로 연결한다.
- 기본·내 템플릿 어느 쪽이든 작성 중 변경은 현재 문서에만 적용한다. 템플릿 원본과 다른 문서는 변경하지 않는다.
- 항목 추가·삭제, 영역 크기·위치·배치 수정은 제공하지 않는다. 구조 변경이 필요하면 Word에서 수정 후 새 양식으로 등록한다.
- 확인용 체크박스는 추가하지 않는다.

## 구현 전 결정할 사항

- DOCX 미리보기 변환 도구와 지원할 양식 구성: 본문·표·머리글·바닥글 등 위치별 입력 표시 처리 범위.
- 업로드 크기와 문서 페이지 수, 항목 수, 긴 글 길이 제한.
- 사용자 템플릿 삭제가 이미 작성한 문서에 영향을 주지 않도록 원본 양식을 보관하는 방식.
- 항목 연결 키와 표시 이름을 분리한 DB·엔티티 구조를 API와 화면에 연결한다. 1단계 데이터 구조 문서를 참고한다.
- 미리보기 갱신 및 파일 생성의 동기 / 비동기 처리 방식.

양식이 없는 자유 작성, AI 자동 분석, 입력 위치 강조, 반복 표·이미지 삽입, 실시간 미리보기는 후속 검토한다.
이번 작업은 화면·동작 정책 설계이며 서비스 코드, 데이터베이스, API 구현은 변경하지 않는다.
